# Constitution — how this template is put together

A two-service web application: a **FastAPI** backend over Postgres, and a **React** frontend that talks to
it over HTTP. Both ship as containers, wired together by `docker-compose.yml` with a Traefik proxy in
front.

## The contract between the two services is generated, not written

This is the single most important thing to know about the codebase. The frontend does not hand-write a
client. `scripts/generate-client.sh` runs the backend, dumps its OpenAPI schema, and regenerates the
TypeScript SDK from it:

```bash
python -c "import app.main; import json; print(json.dumps(app.main.app.openapi()))" > ../openapi.json   # :7
mv openapi.json frontend/                                                                               # :9
npm run generate-client                                                                                 # :11
```

`frontend/src/client/sdk.gen.ts` is therefore a build product — its header says
`// This file is auto-generated by @hey-api/openapi-ts`. **A backend route change reaches the frontend
through a build step, not through someone remembering.** The failure mode is a stale `openapi.json`, which
is visible in a diff, rather than a type mismatch nobody notices.

## Backend layering

Read off the imports at `0.9.0`, not off a diagram:

```
main.py                  FastAPI app: middleware, router mounting
  └── api/               routers + dependency injection (auth, session)
        └── crud.py, models.py, utils.py     domain
              └── core/  config, engine, password hashing
```

`core/` is meant to be the bottom. **It is not, in one place:** `core/db.py:3` does `from app import crud`
so that `init_db` can seed the first superuser through the ordinary creation path
(`core/db.py:33`). Infrastructure therefore depends upward on domain logic. It is a deliberate trade — the
seeding path gets password hashing and validation for free instead of duplicating them — and it is the one
edge that breaks the layering.

## Authentication is a dependency, not a decorator

Access control is expressed by what a route asks for. `deps.py` builds a ladder:

- `SessionDep` — a database session
- `CurrentUser` (`deps.py:30`) — decodes the JWT, loads the user, rejects inactive ones
- `get_current_active_superuser` (`deps.py:52`) — the same, plus a privilege check

A route declares the level it needs in its signature. There is no middleware deciding who may call what,
so **the authorisation for any endpoint is readable from that endpoint alone**.

## Environment decides the route surface

`api/main.py:13` mounts `private.router` only when `ENVIRONMENT == "local"`, and `main.py:14` initialises
Sentry only when it is *not* local. The deployed API is therefore a strict subset of the local one, which
matters when reading the generated client: it is generated from whatever environment ran the script.
